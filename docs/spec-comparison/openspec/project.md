# Project Context -- Dotfiles

> The "worldview" doc OpenSpec uses to inject context into every artifact it
> generates. Equivalent in role to SpecKit's `constitution.md` but written as
> descriptive context rather than prescriptive principles.

## Tech Stack

- **Primary language**: POSIX-compatible Bash (must run on macOS bash 3.2 and
  Linux bash 4+/5+); zsh for shell config (5.x+).
- **Lint**: shellcheck, applied to every `*.sh` file in the repo (excluding
  `.git/` and `.devcontainer/` configs).
- **Tests**: hand-rolled bash test scripts under `tests/` (7 suites). Not
  bats-style -- functions defined in test files, asserted with `[[ ... ]]` and
  `exit 1` on failure.
- **Distribution**: GitHub releases with SHA-256 checksum verification for Linux
  binaries (musl-static where available); Homebrew on macOS; native package
  managers (apt, apk) as fallback.
- **Config formats**: TOML (starship), JSON (Claude Code settings, devcontainer
  manifests), YAML (CI workflows, dc-audit rubric), plain shell for everything
  else.
- **Targets**: macOS 15+ / 26, Ubuntu 20.04 / 22.04 / 24.04, Debian 11 / 12,
  Alpine latest, GitHub Codespaces. WSL2 is covered by the Linux matrix.

## Architecture Patterns

- **Three-tier responsibility model.** This repo installs (a) universally useful
  CLI tools and (b) agentic coding tools (Claude Code, Codex CLI). It does NOT
  install (c) project-dependent tools (gh, docker, kubectl, mise, uv) -- those
  belong in each project's `devcontainer.json`. The repo only supplies the
  configuration surface (aliases, completions, state persistence) so projects
  can light up the developer's preferred workflow when they bring tooling in.
- **Three-file git config model.** `~/.gitconfig` (user identity), `~/.config/git/config`
  (XDG with `[include]` pointing at dotfiles), `git/.gitconfig` (shared
  settings). Identity is never touched by the installer.
- **Tiered state persistence in devcontainers.** Volume mount > Codespaces
  `.persistedshare` > ephemeral `~/.dotfiles-state/`. Auto-detected; no user
  configuration required. Auth tokens, shell history, and Claude Code session
  state survive container rebuilds when a tier is available.
- **Defense-in-depth security.** `Read/Write/Edit` deny globs in `settings.json`
  + `pre-security.sh` hook that scans Bash command strings for sensitive paths +
  global `commit-msg` hook (conventional commits, no AI attribution, no emoji)
  + global `pre-commit` hook (gitleaks). No single layer is the boundary.
- **Lazy initialization in zsh.** zoxide and direnv hooks initialize on first
  prompt (deferred via `precmd`), not during shell startup. `compinit` rebuilds
  the cache once per day, not every shell start. Shaves ~150-300ms off interactive
  startup; profile with `ZSH_PROFILE=1 zsh -i -c exit`.
- **4-stage Claude Code pipeline.** `/pipeline` runs PM Spec -> Architect Review
  -> Implementer + Tests -> QA Reviewer with user checkpoints between stages. Each
  stage is a separate sub-agent with constrained tools.
- **Opt-in for high-risk surface.** The `agentic/` harness (autonomous loop
  runner, hardened devcontainer profile, mitmproxy egress allowlist) is NOT
  installed by default -- only when `./install.sh --with-agentic` or
  `DOTFILES_INSTALL_AGENTIC=1` is set. Opinionated aliases (shadowing `grep` /
  `find`) are similarly opt-in via `DOTFILES_OPINIONATED_ALIASES=1`.

## Code Standards

- **Shell scripts**: shebang `#!/usr/bin/env bash`, `set -euo pipefail` near the
  top, shellcheck-clean. Functions snake_case. No subshells when a `command`
  builtin will do. Quote all variable expansions.
- **Conventional commits**: enforced globally via `commit-msg` hook. Format
  `type(scope): description`, minimum 10-character subject. Allowed types: feat,
  fix, refactor, docs, test, chore, ci, build, perf, style.
- **No AI attribution.** No `Co-Authored-By: Claude` lines, no "Generated by
  Claude Code" trailers. Blocked by both the commit-msg hook and the Claude Code
  `pre-commit-validate.sh` hook.
- **No decorative emoji** in code, docs, or commit messages. Blocked by the
  `pre-code-no-emoji.sh` hook on Write/Edit and the `commit-msg` hook on
  commits.
- **No backwards-compat shims.** When code is removed, it is removed cleanly --
  no `// removed for X` comments, no renamed-to-`_unused` parameters. The git
  history is the audit trail.
- **Idempotent installers.** `./install.sh` is safe to re-run any number of
  times. Existing files are backed up to `~/.dotfiles_backup_<timestamp>/`
  before being replaced.

## Domain Knowledge

- **Devcontainer vs Codespaces vs local.** The installer auto-detects which it
  is via env vars (`CODESPACES`, `REMOTE_CONTAINERS`, `DEVCONTAINER`) and the
  presence of `/.dockerenv`. Each environment has different state-persistence,
  git-identity, and AI-tool-installation paths.
- **VS Code SSH agent forwarding.** Local devcontainers get the host's SSH agent
  forwarded into the container, which is how SSH commit signing works without
  ever copying private keys. Codespaces uses GitHub-managed SSH keys instead.
- **Claude Code hook contract.** Hooks receive a JSON object on stdin
  describing the tool call (`tool_name`, `tool_input`) and respond by emitting
  a JSON object on stdout: `{hookSpecificOutput: {hookEventName, permissionDecision,
  permissionDecisionReason}}`. Decisions are `allow`, `ask`, or `deny`. Exit
  code 0 means "let the framework decide based on stdout"; non-zero is a hard
  failure.
- **dc-audit profiles.** `attended` (default) accepts ergonomic dev profiles
  with credential mounts and light safety. `unattended` enforces `--cap-drop=ALL`,
  resource caps, no host credential mounts, and expects egress control. Used by
  CI and by autonomous agentic loops.
- **Conventional commit footers.** The commit-msg hook treats `BREAKING CHANGE:`
  in the footer specially; other footers (`Refs:`, `Reviewed-by:`, etc.) pass
  through unchanged. AI-attribution patterns are matched case-insensitively.

## Infrastructure / Deployment

- **CI**: GitHub Actions, matrix of 13+ platform configurations (cross-product
  of distro x shell x package manager). Workflows live in `.github/workflows/`.
  Lint job runs shellcheck on every `*.sh`. Test job runs `make test` per
  matrix cell.
- **No external services in CI.** The installer is tested by *running it* in
  fresh container images, then asserting symlinks exist, tools resolve, shell
  startup completes without error, and `dotfiles-doctor` reports green.
- **Release model**: rolling. The repo is the source of truth; users `git pull`
  and `./install.sh` to update. No tagged releases.

## Known Constraints

- **No MCP servers installed by default.** MCP servers run as child processes
  with full filesystem and network access, and they bypass the
  `settings.json` deny rules. Installing one is a security decision; the repo
  forbids it without explicit user request.
- **No project tooling.** The repo will not install gh, docker, kubectl, mise,
  uv, or similar. An alias for a missing tool is harmless ("command not found"
  is fine); an installer that drags in tools the user did not ask for is not.
- **No symlinks for individual files** when atomic writes (Write tool, `mv`,
  `cp -f`) are involved. Atomic writes break file symlinks by replacing the
  symlink with a regular file. Directory symlinks and env-var indirection are
  fine.
- **No direct pushes to `main`.** All work goes through feature branches and
  PRs.
- **macOS bash is 3.2.** Cannot use associative arrays, `[[ ... =~ ... ]]` with
  BASH_REMATCH for complex patterns, or `${var,,}` style modifiers. Test on
  macOS or you will discover this in CI.
- **Path traversal denied by default.** Patterns matching `../` are blocked by
  the `pre-security.sh` hook unless the user explicitly authorizes.
